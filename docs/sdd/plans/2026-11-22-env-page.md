# Environment page instead of three sections — implementation plan

**Goal:** `/` is the board, `/env/:id` shows releases + this env's history + its settings form (with servers/agents managed inside it), `/env/new` creates an env; `/history`, `/settings/servers`, `/settings/env/new`, `/settings/env/:id` (GET) are gone.
**Spec:** docs/sdd/specs/2026-11-22-env-page.md
**Prototype:** docs/sdd/proto/env-page/decision.md (variant A2)
**Verification:** `pnpm typecheck && pnpm test` — last line of vitest `Tests  N passed (N)`, no failures. `pnpm test:e2e` cannot run on this machine (Docker cannot mount `/tmp`); e2e edits are checked by typecheck only.

Codex is off (mode explore): every task runs on Claude.
dryer: two near-duplicates inside `packages/server/src/ui/panel.ts` / `env.ts` (score 0.82) are untouched by this work — no instruction.

## Context

The UI splits one environment across three nav sections and two hidden pages; the env settings form has no link to it at all. The agreed spec and prototype A2 merge everything about one environment into one long page and move server/agent management into the env form.

## Global constraints
- No code comments (user rule).
- Styling: the project has no Tailwind; it uses `packages/server/src/public/app.css` with tokens `--bg --panel --card --ink --mute --line --accent --on-accent --prod --prod-soft`. New rules go there, matching its one-line style. (Adding Tailwind is a separate decision, not part of this plan.)
- Every user-visible string comes from the i18n catalogs via `tr(i, key, params)` / `i.t(...)`; every key exists in all 8 languages `uk, en, de, fr, es, pt-BR, pl, zh-CN` (test `every language has exactly the keys of en` in `packages/core/src/i18n/i18n.test.ts:259`).
- htmx 2 is loaded (`/static/htmx.min.js`). htmx requests carry CSRF as `hx-headers='{"x-csrf-token":"<csrf>"}'`, exactly as `post()` in `packages/server/src/ui/panel.ts:7-8` builds it.
- All HTML goes through `html\`\`` from `packages/server/src/ui/html.ts` (auto-escaping); `raw()` only for already-escaped strings.
- Keep existing test ids: `server-name`, `server-create`, `agent-token`, `agent-command`, `server-error`, `env-save`, `deploy-token`, `env-bind-db`, `bind-result`, `env-error`, `env-new`, `env-settings-<name>`.

## Review Focus
- A server-block button inside the env form must not send the env form's `name`: creating a server while the env name field holds "production" must create the server from `server_name` only (Task 0 test).
- Enter pressed in `server_name` must not submit the env form (Task 3 test on the `onkeydown`).
- Changing the server `<select>` must swap only `#srv` and not submit the env form (Task 3 asserts `hx-get` on the select and `type="button"` on every block button).
- An env with no finished operations shows `env.historyEmpty`, not an empty table (Task 2 test).
- `GET /env/new` returns the form, not the 404 of an env with id `new` (Task 0 test).
