# microrun-ui — prototype decision

**Chosen:** variant D2 — B (колонки оточень + бічна панель) як основа, плюс з A окрема сторінка оточення з таблицею релізів, історія з фільтром за оточенням і світла тема; i18n на 8 мов.

**Why:** користувач обрав B + A: на одному екрані видно стан усіх оточень, а сторінка оточення з таблицею дає щільний перегляд змін схеми й вікна для довгого списку релізів. Відкат і прибирання даних живуть в одній бічній панелі незалежно від того, звідки її відкрито.

**Structure:**
- `/` — колонки dev / stage / production, production з червоною рамкою і тегом `PRODUCTION`; кожен реліз — картка зі станом, автором, відносним часом і смужкою залишку вікна.
- `/env/<id>` — заголовок з метаданими (гілка, сервер і тип агента, compose-сервіси зі стратегіями, база, сховище, вікно), попередження, таблиця релізів (реліз, стан, зміни схеми, вікно).
- `/history` — таблиця операцій з фільтром за оточенням; причина відмови чи збою — під статусом.
- Бічна панель релізу: деталі, diff схеми, нотатки (заблоковано / dry-run відхилив), блок відкату з переліком релізів, що буде заблоковано; для production — введення назви оточення; хід відкату по кроках; потім окремий крок прибирання даних з чекбоксами правил і лічильником.
- Тема: світла / темна за `prefers-color-scheme`.

**Changed while debugging:**
- На ширині ≥ 1100 px відкрита панель зсуває вміст (`margin-right: 440px`), інакше вона закривала колонку production саме під час відкату production.
- Заголовок панелі після завершення змінюється на «Відкат завершено за N с» (лишався «виконується…»).
- Залишок вікна без нульових годин («87 днів», не «87 днів 0 годин»).
- На вузькому екрані (390 px) — одна колонка, production першою, метадані оточення в стовпчик, без горизонтальної прокрутки.
- Причина недоступності відкату конкретна: «агент офлайн» або «база не відповідає оточенню».

**i18n:**
- Мови: `uk`, `en`, `de`, `fr`, `es`, `pt-BR`, `pl`, `zh-CN`. Типова — з `Accept-Language` / `navigator.languages`, з відкатом на `en`; вибір зберігається.
- Множина через `Intl.PluralRules` (форми `one/few/many/other`), числа, дати, тривалості (`Intl.NumberFormat` з `style: 'unit'`) і відносний час (`Intl.RelativeTimeFormat`) — через `Intl`, без ручних форм.
- Дані користувача (повідомлення комітів, описи правил cleanup, назви оточень) не перекладаються.
- Параметри повідомлень екрануються під час підстановки.
- Перевірено: у всіх 8 мовах на всіх екранах немає сирих ключів, `undefined` чи `NaN`.

**Ruled out:**
- C (майстер на всю сторінку) — більше кліків, немає загального огляду оточень.
- A як основа — модальне вікно тісне для прибирання з кількома правилами.

**Open:** екрани налаштувань (сервери/агенти, редактор оточення, сховище) і вхід не прототипувалися — вони стандартні форми; RTL-мови не входять у набір.
