# ui-redesign — prototype decision

**Chosen:** варіант C, ітерація `variants/c4/index.html` (джерело `src/c4.html`, спільні `shared/data.js`, `shared/views.js`, `shared/base.css`; збірка `python3 src/build.py c4`).

**Why:** на 100 оточеннях і ~1100 релізах колонки на дошці (поточний `/`) і матриця за проєктами (варіант A) не масштабуються або потребують поняття «проєкт», якого немає в моделі. Список + деталі (B) показує лише одне оточення за раз. C дає на одному екрані останні деплої й покажчик усіх оточень, а сторінка оточення лишається такою ж, як у продукті.

**Structure:**
- Шапка: фон на всю ширину, вміст у колонці 1320 px, як і контент: логотип, пошук (назва / гілка / SHA, `/` фокусує), перемикач мови, «New environment».
- `/`: ліворуч «Latest deploys» — релізи всіх оточень за часом, фільтр Production / Staging / Development / Previews, по 25 рядків із «Show 25 more»; праворуч «All environments» — покажчик A–Z за групами з крапкою стану (зелена / жовта — проблема / червона — невідповідність бази / порожня — агент офлайн). Клік по рядку стрічки відкриває бічну панель релізу.
- `/env/<id>`: шапка з метаданими (гілка, сервер і стан агента, сервіси зі стратегіями, вікно відкату, сховище образів), попередження, липка навігація Releases / Settings. Релізи: «Within the rollback window» повністю, «Older releases» згорнуті й показуються по 20. Settings — секції з `settings.ts` (General з блоком сервера, Compose, Database, Commands and checks, Image storage and rollback window), «Save changes», «Reissue deploy token», Danger zone.
- Бічна панель релізу (440 px; на ≥1100 px зсуває вміст і шапку): назва оточення — посилання на його сторінку; SHA і стан; нотатки (заблоковано / dry run / вікно закрито / образ не збережено); зміни схеми; відкат (зокрема з активного релізу) з переліком комітів, що буде заблоковано; production — двокрокове підтвердження «Roll back production <env> to <sha>?» → «Yes, roll back» / «Cancel»; кроки відкату; потім необов’язкове прибирання даних із чекбоксами правил; approve для destructive-зміни; повтор contract; історія операцій релізу.
- Тексти (EN): стани `Live` / `Can roll back` / `Rolled back` / `Window closed` / `Deploy failed`; інші рядки — у `C` в `shared/data.js`.

**Changed while debugging:**
- Мобільна шапка займала три рядки → два: логотип, мова, «New» / пошук.
- Відкрита панель ховала праву частину шапки → шапка зсувається разом із вмістом.
- З панелі не можна було перейти до оточення → назва оточення стала посиланням.
- Рядок стрічки, відкритий у панелі, підсвічується.
- Шапка була на всю ширину, а контент — у колонці 1320 px → вміст шапки вирівняно по колонці контенту, також при відкритій панелі; на 390 px обидва краї 16 px.
- Блок «Needs attention» (зведення проблем по всіх оточеннях) прибрано: прототип показує наявну функціональність, а такого зведення в продукті немає.
- Після відкату заголовок панелі показує новий стан релізу, а не попередній.

**Ruled out:**
- A (матриця проєкт × етап) — потребує поля «проєкт», якого немає; групування за префіксом назви крихке.
- B (список + деталі) — немає загального огляду, видно одне оточення за раз.
- Поточна дошка з колонками — 100 колонок по ~10 карток не читаються.

**Open:**
- Стрічка «Latest deploys» по всіх оточеннях і поділ на Staging / Development / Previews — нові для продукту: у моделі є лише `is_production` і `position`, а окремої сторінки історії немає (її замінила історія в панелі). У прототипі етап виводиться з назви. Рішення — у специфікації.
- У стрічці на «All» переважають preview-оточення, бо вони деплояться найчастіше.
- Перевірено на 1440, 1864 і 390 px, у світлій і темній темах; ширини між 761 і 1099 px окремо не перевірялися.
