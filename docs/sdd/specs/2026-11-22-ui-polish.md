# UI polish: вхід, форми, видалення, мови — design

**Date:** 2026-11-22
**Status:** agreed
**Prototype:** docs/sdd/proto/login/decision.md

## 1. Problem

- Сторінка входу (`packages/server/src/ui/login.ts`) — голий заголовок і два поля посеред екрана, без жодного брендування.
- Форми зібрані вручну з різних шматків: `entry`, `dropdown`, `password`, `checkbox` у `ui/settings.ts`, окремі `<label><input>` у `login.ts`, свій `<select>` у `layout.ts`. Стиль у `public/app.css` описує тільки `input[type=text]`, тому `select`, `password` і `number` виглядають як браузерні за замовчуванням, а відступи між полями різні.
- У налаштуваннях немає способу видалити сервер (агента) чи середовище: у `db/repo.ts` немає `deleteServer` / `deleteEnv`, а в `routes/ui.ts` немає відповідних маршрутів.
- У `LANGS` першою стоїть `uk`. Вебмова визначається з `Accept-Language`, тому користувач з українським браузером бачить українську, хоча продукт орієнтований на англійську. На сторінці входу перемикача мови немає взагалі, а `POST /lang` вимагає сесію та CSRF.

## 2. Constraint that shapes the solution

Сторінки рендеряться на сервері шаблонним тегом `html` у TypeScript, без фронтенд-фреймворку й без кроку збирання CSS. Глобальне правило користувача вимагає стилізувати через утиліти Tailwind. Тому Flowbite беремо як **набір класів** (його форми — це Tailwind-утиліти), без його JS і без npm-залежності `flowbite`. Tailwind CSS v4 збирається CLI під час `build`. Альтернативу — дописати руками ще CSS у `app.css` — відкинуто: вона суперечить правилу й не дає єдиного джерела стилю для полів.

Видалення зачіпає збережені дані (зовнішні ключі `environments → servers`; `operations`, `releases`, `destructive_approvals → environments`; `releases.blocked_by_op → operations`). Тому видалення сервера з середовищами заборонене, а середовище видаляється однією транзакцією лише тоді, коли в нього немає активної операції.

## 3. Solution

### 3.1 Tailwind-пайплайн

- Залежності dev у `packages/server`: `tailwindcss@4`, `@tailwindcss/cli@4`.
- Джерело: `packages/server/src/public/app.src.css` містить `@import "tailwindcss"`, `@source "../ui"` і `@theme inline` з токенами кольорів (`--color-bg`, `surface`, `field`, `ink`, `mute`, `line`, `accent`, `on-accent`, `prod`, `prod-soft`, `ok`, `warn`, `warn-soft`, `code`) та шрифтів (`sans` Inter, `display` Space Grotesk, `mono` JetBrains Mono, кожен із системним fallback). Темна тема задається через `prefers-color-scheme`. *(Моє рішення після builder check.)* Значення беремо з поточного `app.css`, а не з прототипу: `surface` = старий `--panel`; `card` лишається окремим токеном (`.rel`, фільтри, кнопки ghost); `field` = `#fff` у світлій темі і `#0f1419` у темній. Додається `ring`: `rgba(47,111,235,.22)` у світлій і `rgba(88,166,255,.25)` у темній. Фокус полів — `focus:ring-4 focus:ring-ring`. Кольори прототипу, що відрізняються (`mute`, `line`, темний `bg`), не переносимо. Ліва панель логіну має власні токени `--c-*` з прототипу. Шрифти тягнемо з Google Fonts `<link>` у `layout.ts` і `login.ts`.
- Плоский CSS лишається в `app.src.css` лише для того, чого Tailwind не виражає: keyframes (блимання LED, бічна панель `#panel`), псевдоелементи таймлайну (`.tl::before`, `.rel::before`). Решта старих класів переписується утилітами в шаблонах.
- Скрипти `packages/server/package.json`:
  - `"css": "tailwindcss -i src/public/app.src.css -o src/public/app.css --minify"`;
  - `"build": "pnpm css && tsup"`; `postbuild` без змін копіює `src/public/app.css` у `dist/public`;
  - `"dev:css": "tailwindcss -i src/public/app.src.css -o src/public/app.css --watch"`.
- `packages/server/src/public/app.css` видаляється з git і додається в `.gitignore`. `app.ts` і далі віддає `/static/app.css` з `here('./public/app.css')`.
- Правило з прототипу: блок, прихований атрибутом `hidden`, не отримує display-утиліту (`flex`, `grid`, `block`) напряму. Якщо його показує скрипт, використовуємо `[&:not([hidden])]:flex`. Блоки, що залежать від серверного стану (помилки), сервер просто не рендерить.

### 3.2 `ui/form.ts` — єдині контроли

Новий модуль; лише чисті функції, що повертають `Html`.

| функція | сигнатура | розмітка |
|---|---|---|
| `field` | `(p: { id: string; label: Html; control: Html; hint?: Html; error?: Html }) => Html` | `<div class="flex flex-col gap-1.5">` + `<label for=id>` + control + hint/error `<p class="text-xs …">` |
| `input` | `(p: { id: string; name: string; value?: string; type?: 'text'\|'password'\|'number'\|'url'; required?: boolean; autocomplete?: string; placeholder?: string; testid?: string; invalid?: boolean }) => Html` | Flowbite input: `block w-full rounded-md border border-line bg-field px-3.5 py-2.5 text-sm text-ink focus:border-accent focus:ring-4 focus:ring-accent/20`; `invalid` → `border-prod` |
| `select` | `(p: { id: string; name: string; options: {value: string; label: Html\|string}[]; current?: string; attrs?: Html; testid?: string }) => Html` | ті самі класи, що в `input` |
| `checkbox` | `(p: { id: string; name: string; checked: boolean; label: Html }) => Html` | Flowbite checkbox: `size-4 rounded border-line text-accent focus:ring-accent/30` + label у рядок |
| `button` | `(p: { label: Html; variant?: 'primary'\|'danger'\|'ghost'; type?: 'submit'\|'button'; testid?: string; attrs?: Html }) => Html` | `rounded-md px-4 py-2.5 text-sm font-semibold`; primary `bg-accent text-on-accent`, danger `bg-prod text-white`, ghost `border border-line` |

- Відступи: усі форми — це `flex flex-col gap-5`; у групах полів у рядок — `grid gap-5 sm:grid-cols-2`. Без `margin` на окремих полях.
- `settings.ts` видаляє `entry`, `dropdown`, `password`, `checkbox` і локальний `field` та переходить на `form.ts`. `layout.ts` рендерить мовний `select` через `select`. `login.ts` використовує `field`, `input`, `button`.
- Наявні `name`, `data-testid` і `aria-label` зберігаються.

### 3.3 Сторінка входу (варіант B3 з прототипу)

`loginView(i, { error, csrf })` повертає двоколонкову сторінку:

- Ліва панель `hidden lg:flex w-[42%] max-w-[560px]`, завжди темна (власні токени `--c-*`). Усередині: логотип `▍microrun` (mono, маркер акцентний), вбудована SVG сервера з рядками dev/stage/prod (гілка ліворуч, хеш вирівняний праворуч перед двома LED; prod у червоній рамці), блок журналу деплою (5 рядків mono, ротація раз на 1.8 с маленьким inline-скриптом; при `prefers-reduced-motion` статичний), а знизу слоган `login.tagline` і підрядок `login.subline`.
- Права частина: перемикач мови вгорі праворуч (`GET`-форма, див. 3.5), заголовок `login.title`, помилка (рендериться сервером тільки при `error`), поля `login.username` і `login.password` з підписами uppercase, кнопка «показати пароль» (SVG-іконка, `aria-label` = `login.showPassword`), кнопка `login.submit`. На мобільному — логотип над заголовком.
- Демо-рядки журналу і назви середовищ на SVG — статичні ілюстративні дані, не живі дані сервера.
- Нові ключі в усіх 8 каталогах `catalogs/settings.ts`: `login.tagline`, `login.subline`, `login.showPassword`. Тексти en/uk/de/fr/es/pt-BR/pl/zh-CN беремо з `docs/sdd/proto/login/variants/b3/index.html`, `showPassword` перекладаємо окремо.

### 3.4 Видалення сервера й середовища

**Repo (`db/repo.ts`):**
- `deleteServer(id): Promise<'deleted' | 'builtin' | 'has-envs' | 'missing'>` — у транзакції перевіряє `builtin`, кількість `environments` з цим `server_id`, потім видаляє рядок.
- `deleteEnv(id): Promise<'deleted' | 'busy' | 'missing'>` — у транзакції повертає `busy`, якщо є операція зі статусом `pending|running`; інакше видаляє в порядку `destructive_approvals` → `releases` → `operations` → `environments` (порядок обходить `releases.blocked_by_op`).
- Обидва ідемпотентні: повторний виклик повертає `missing` і нічого не змінює.

**Маршрути (`routes/ui.ts`, CSRF як у решти POST):**
- `POST /settings/servers/:id/delete` → `deleted`: `hub.disconnect(id)` і редирект 303 на `/settings/servers`; `builtin` / `has-envs` → сторінка серверів зі статусом 409 і помилкою `settings.servers.deleteBuiltin` / `settings.servers.deleteHasEnvs` (з кількістю середовищ); `missing` → 404.
- `POST /settings/env/:id/delete` → `deleted`: редирект 303 на `/`; `busy` → форма середовища з 409 і `settings.env.deleteBusy`; `missing` → 404.
- Контейнери, образи й рядок-маркер у базі даних середовища не чіпаються. Це сказано в тексті діалогу.

**Сирітський маркер БД (`orchestrator.bindDatabase`):** зараз будь-який маркер з `envId !== env.dbMarkerId` дає `DB_MARKER_MISMATCH`. Нове правило: якщо `repo.findEnvByMarker(marker.envId)` повертає `null` (жодне середовище не має такого `db_marker_id`), маркер вважається сирітським. Тоді прив'язка йде звичайним шляхом: `writeMarker` (агент уже робить `DELETE` + `INSERT`, див. `packages/agent/src/db.ts:268`) і `setEnvMarker`. Маркер живого іншого середовища, як і раніше, дає `DB_MARKER_MISMATCH`. `checkMarkers` під час деплою не змінюється: після перепривʼязки маркер уже належить поточному середовищу. Протокол і агент не змінюються. Новий метод `repo.findEnvByMarker(markerId: string): Promise<EnvRow | null>`.

**UI:**
- `serversView`: остання колонка рядка — кнопка `danger` «Видалити» (`data-testid="server-delete-<name>"`) для невбудованих серверів.
- `envFormView` (редагування, не створення): унизу секція «Небезпечна зона» з кнопкою `danger` (`data-testid="env-delete"`).
- Кнопка відкриває нативний `<dialog>` (`showModal()` у inline-обробнику `onclick`). У діалозі: заголовок, текст наслідків (`settings.servers.deleteBody` / `settings.env.deleteBody`), поле `confirm_name`, кнопки «Скасувати» (ghost, закриває діалог) і «Видалити» (danger, `disabled`, доки введене значення не дорівнює назві). Сервер повторно перевіряє `confirm_name === name`, інакше відповідає 400 без змін.
- Нові ключі в усіх 8 каталогах: `settings.delete`, `settings.cancel`, `settings.confirmName`, `settings.servers.deleteTitle`, `settings.servers.deleteBody`, `settings.servers.deleteBuiltin`, `settings.servers.deleteHasEnvs`, `settings.env.dangerZone`, `settings.env.deleteTitle`, `settings.env.deleteBody`, `settings.env.deleteBusy`.

### 3.5 Мови

- `LANGS = ['en', 'uk', 'de', 'fr', 'es', 'pt-BR', 'pl', 'zh-CN']`. Від цього порядку залежить лише порядок у перемикачах; узгодження мови (`negotiate`, `matchTag`) від нього не залежить.
- Нова `webLang(cookie: string | undefined): Lang` у `core/i18n` повертає `isLang(cookie) ? cookie : 'en'`. Нею користуються `langOf` у `routes/ui.ts` і рендер логіну в `auth.ts`. `Accept-Language` для вебу більше не читається. `routes/api.ts` і `fromEnvLocale` (CLI агента) лишаються на `negotiate`.
- `GET /login?lang=<Lang>`: якщо `isLang`, ставить cookie `mr_lang` з тими самими параметрами, що й `POST /lang`, і рендерить сторінку цією мовою; невідоме значення ігнорується. Перемикач на логіні — `<form method="get" action="/login">` із `select name="lang"`, `onchange="this.form.submit()"` і `<noscript>`-кнопкою.

## 4. Out of scope

- Видалення контейнерів, образів, баз і маркерів на хості при видаленні середовища (сирітський маркер перезаписується при наступній прив'язці, див. 3.4).
- Відновлення видаленого, soft-delete, архів.
- Редизайн дошки, історії й бічної панелі релізу. Тут вони тільки переходять на Tailwind-утиліти й `form.ts`, візуально лишаючись близькими до поточних.
- Компоненти Flowbite з JS (dropdown, modal, tooltip) і пакет `flowbite`.
- Користувачі й ролі: адмін, як і раніше, один.

## 5. Trade-offs accepted

- `pnpm build` (і dev) тепер потребує кроку `css`; без нього `/static/app.css` віддає 404. Згенерований CSS не в git, тому diff чистий.
- Шрифти з Google Fonts: офлайн-інсталяції бачать системний fallback.
- Користувач з неанглійським браузером при першому візиті бачить англійську і перемикає мову вручну. Користувач цього прямо хоче.
- Видалення середовища безповоротно стирає його історію операцій і релізів.
- Ліва панель логіну темна і в світлій темі — так задумано в прототипі.

## 6. Verification

- `pnpm verify` зелений.
- Unit (`db/repo.test.ts`): `deleteServer` → `builtin`, `has-envs`, `deleted`, повторно `missing`; `deleteEnv` з `running`-операцією → `busy`; без неї → `deleted` і нуль рядків у `operations`/`releases`/`destructive_approvals` для цього `env_id`, повторно `missing`.
- Orchestrator (`orchestrator.test.ts`): `bindDatabase` при маркері видаленого середовища → `ok` і новий `writeMarker`; при маркері живого іншого середовища → `DB_MARKER_MISMATCH`.
- Маршрути (`app.test.ts` / `settings.test.ts`): 303 + `hub.disconnect` на видаленні сервера; 409 з текстом помилки для `has-envs`, `builtin`, `busy`; 400 при неправильному `confirm_name`; 403 без CSRF.
- i18n: `LANGS[0] === 'en'`; `webLang(undefined) === 'en'`, `webLang('uk') === 'uk'`, `webLang('xx') === 'en'`; усі нові ключі є в 8 каталогах (`i18n-usage.test.ts`). У `auth.test.ts` рядки `Accept-Language` переписуються: для вебу без cookie очікується `en`; `GET /login?lang=de` ставить `mr_lang=de` і віддає німецьку сторінку.
- Views: `loginView` без `error` не містить `data-testid="login-error"`; з `error` — містить; немає жодного елемента з `hidden` і display-утилітою без `:not([hidden])`.
- E2E (`e2e/acceptance.spec.ts`): вхід через нову сторінку; перемикач мови на логіні; видалення сервера без середовищ через діалог (кнопка неактивна до введення назви).
- Візуально: `/login`, `/settings/servers`, форма середовища — на 1440 і 390 px, у світлій і темній темах, без горизонтального скролу.
